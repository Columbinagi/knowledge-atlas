# 知识图鉴模板 · 示例包

**单文件、零外部请求的术语图鉴模板。** 内容只写 Markdown，一条命令拼成一个可双击打开的单页站点；不需要数据库、不需要构建工具、不需要 `npm install`。

> **版本与基线**：本包是模板包 **v0.1.0**。内容基线为 `glossary-atlas-template` **v2.0.0（commit `4e5dde7`）**，另含本项目尚未回灌上游的分叉 **B6–B23**（桌面阅读体验、手机端与宽屏几何、图鉴切换器、多图鉴底层、三段式卡片 ID 等），**与公开仓库 v2.1.0 不是同一条线**，请勿按 v2.1.0 逐字节对照。
> v0.1.0 是**模板包版本**，不是站点号——站点号另计。

## 三步上手

**① 装 Node**（唯一硬依赖，实测 v24；建议 ≥18）。没有 `package.json`，不需要装任何包。

**② 写卡**：在 `content/图鉴/demo/知识库/<主题>/` 下新建 `<卡号>-<id>.md`，同时在 `content/图鉴/demo/词条清单.md` 加一行。

**③ 跑拼合**：

```bash
node engineering/拼合.mjs
```

产物在 `dist/新能源汽车知识图鉴.html`，双击即开。想先看效果，直接用包内自带的三张示例卡跑一遍即可。

> 产物文件名是**脚本里的固定值**，不是由品牌名推导的（见下面「派生必改」第 1 条）。

三张示例卡分别对应三种形态：**纯文字卡**（三电系统总览）、**图解卡**（图鉴总览）、**带状态机的可操作演示卡**（多合一电驱）。

## 一张卡怎么写

```markdown
## 015. 永磁同步电机

- id: `pmsm`
- 分类: `c1`          ← 用分类归属主题；不写分类时改写成 `- 主题: `t2``
- 英文名: PMSM

### 你可能会说

> 车上那台电机，跟工业电机有什么不一样？

### 是什么

一句话定义（必填）。

### 详解

- 分条解释，一条一个意思。
```

其余章节按需添加，**留空就不渲染**。章节名是固定词表，认不出会直接报错：

| 章节 | 作用 | 章节 | 作用 |
|---|---|---|---|
| 你可能会说 | 开场提问（引用块） | 使用场景 | 什么时候用 / 不用，可配 `mk` 小卡 |
| 是什么 | 一句话定义（必填） | 常见变体 | 同一概念的几种形态 |
| 详解 | 分条解释 | 容易混淆 | vs 型对照 |
| 先知道 | 前置概念（可带 `[[id]]` 链接） | 选择题 | 自测题（题干 + 选项 + 答案 + 解析） |
| 别名 | 顿号分隔 | 告诉 AI | 给模型的检索指令 |
| 图解 | ` ```html ` 代码块，内联 SVG 或组件 | 接下来学什么 | `- [[id]] —— 一句话` |
| 一句话 | 图解结论句 | 来源 | `- 名称：https://…` |
| 演示注解 | 图解的口径说明 | 主线位置 | 3–7 步的流程定位 |
| 组成结构 | 舞台图 + 部件列表（`data-ap` 配对） | 可操作演示 | ` ```json ` 状态机（2–9 态） |
| 正文分点 | `####` 小节 + 段落 | | |

## 配置在哪

| 文件 | 改什么 |
|---|---|
| `content/图鉴清单.json` | 图鉴 id、代号（1–99）、内容目录（必须是 `图鉴/<id>`）、身份色、图形键 |
| `content/图鉴/demo/站点配置.js` | 品牌名与副标题、五个 `*En` 英文取词、四个标题模板、主题与分类、默认主题 |
| `content/图鉴/demo/词条清单.md` | 选题、卡号、卡片 ID（`图鉴代号-主题代号-卡号`）、状态 |
| `content/图鉴/demo/更新日志.md` | 更新日志条目（日期倒序，可写 `收录: id1, id2`） |

主题与分类里有两个编号容易漏：`图鉴清单.json` 的 `code` 与 `站点配置.js` 里 `TOPICS[].code`。两处都写全，卡片 ID 才算得出来。

## 校验

```bash
node engineering/校验.mjs            # 常规：浏览器起不来时记「需外部验证」，退出码 0
node engineering/校验.mjs --strict   # 严格：任何一项未验证即退出码 2
```

- 需要无头 Chrome / Edge；默认路径写死 Windows 安装位置，可用 `JC_CHROME` 覆盖：
  `JC_CHROME="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" node engineering/校验.mjs --strict`
- 严格模式的验收口径是 **0 失败 0 未验**（不是「退出码 0」）。
- 校验会跑十几轮无头浏览器断言（自测进度、返回列表、切语言、无障碍等），低配机可加 `JC_SKIP=③-c,③-k` 分小批跑，但 `--strict` 照样会拦。

## 派生必改

1. **产物文件名写死在 4 个脚本里**：`engineering/拼合.mjs:17`、`engineering/校验.mjs:32`（本包内这两处）、以及完整骨架里的 `engineering/体检.mjs:58`、`engineering/预览服务.mjs:33`。四处同值，只改一处会让另一处指空。建议改为由 `SITE_META.brandName` 推导——本包按「不改引擎」出包，暂未改。
2. **搜索探针**：`校验.mjs` 对图鉴 id `nev` 有一条专用探针；本包 id 是 `demo`，走通用分支（自动取首条卡的名字与别名），无需改。若你把 id 改回 `nev`，会命中旧探针。
3. **拼音表只覆盖示例用字**：母版里的 `var PYI` 是按示例内容生成的。新增词条出现缺字时，校验会点名缺哪个字，按提示补进母版再拼合。
4. **品牌名散落在多处**：`站点配置.js` 的 `brandName` / `brandShort` / `pageTitle`、产物文件名、README 首段——改名时一起改。
5. **示例卡要换成你自己的内容**：三张卡是本项目真实内容的脱敏改写，结构与措辞可以照抄，行业例子请替换。
6. **与上游同步**：本包含 B6–B23 未回灌分叉（见 `NOTICE.md`）。把包并入上游或换新母版时，按分叉清单逐条对照，不要整份覆盖。

## 常见问题

- **`ENOENT: dist/…`**：`dist/` 不存在。本包带 `dist/.gitkeep`，若被清理掉，先 `mkdir dist`。
- **英文界面**：`知识库-en/` 是可选分册。没有它时英文界面回退中文，校验输出 `英文分册：无`，不算失败。
- **体积上限**：单文件产物上限 20 MB（`图鉴清单.json` 的 `maxBytes`），超了拼合会报错并保留原产物。
- **为什么只有一个 HTML**：站点是单文件、零外部请求，字体与图示都内联；换机器、断网都能打开。
